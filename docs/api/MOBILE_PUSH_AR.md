# HAG — Push ونسخة Android التجريبية

تحديث بعد إكمال الحساب. Push للعروض ورسائل التفاوض فقط في هذا الإصدار؛ لا Push للشحن أو التسويق أو الإدارة. يحتاج حساب مالك/مدير شركة موثقًا ونشطًا وإذن هاتف فعلي. تنبيهات الجرس والبريد الحالية تبقى مستقلة.

- موافقة المستخدم من حسابي ← إشعارات الهاتف، وخيارات عروض/رسائل لكل جهاز. لا طلب إذن تلقائي عند فتح التطبيق. تعطيل الربط من الشاشة لا يغير إعداد إذن النظام نفسه.
- نص عام لا يتضمن اسم الشركة أو نص الرسالة أو السعر. بيانات Push تحتوي فقط scope وUUID للربط والإشعار. يُتحقق من الطرف والعضوية والرمز عند الإرسال وعند فتح الهدف. لا قراءة ضمنية للرسائل أو الإشعارات بمجرد GET.
- رمز Expo مشفر في قاعدة البيانات، وفهرس تجزئة فريد. الربط مرتبط برمز Sanctum؛ إلغاء الرمز من الخادم يحذف الربط، بما فيه تسجيل الخروج أو تبديل الرموز. انتهاء الصلاحية يُفحص أيضًا قبل إرسال كل طلب.
- إذا خرج المستخدم دون اتصال أو تعذر إلغاء الرمز على الخادم، لا يمكن ضمان توقف الإرسال البعيد فورًا. وقد يصل إشعار عام أُرسل قبل الخروج. الربط القديم لا يفتح تفاصيل في جلسة حساب آخر. لا تدّع ضمان عدم وصول أي إشعار قديم على شاشة النظام.
- جمع آخر 24 ساعة بحد 200 إشعار مرشح في الدورة، وإرسال 5 سجلات انتظار كحد أقصى في الدقيقة على الاستضافة المشتركة. يفحص مجددًا الحالة والخيارات وقراءة الرسالة. ليس وعدًا بالتسليم الفوري أو منصة Push عالية الحجم؛ يمكن توسيع عامل الإرسال لاحقًا.
- التكرار مقيد بمفتاح جهاز/إشعار/ربط وقفل حالة. إرسال غامض يصبح uncertain ولا يعاد تلقائيًا؛ فشل اتصال قد يخفي قبول المزود. قد يفوت إشعار بدل تكراره؛ يبقى التحديث داخل التطبيق.
- يُفحص receipt بعد 15 دقيقة. provider_accepted يعني قبول FCM/APNs، وليس وصول الهاتف أو قراءة المستخدم. DeviceNotRegistered يعطّل التسجيل. فقدان/تقادم receipt لا يؤدي لإعادة إرسال تلقائي. processing/uncertain يتطلبان مراجعة؛ لا تعدهما لصف الانتظار دون فهم خطر التكرار.
- الإرسال معطل افتراضيًا. لا مفاتيح حقيقية أو معرف مشروع مختلق أو FCM/APNs داخل الحزمة. لا تغييرات في Stripe أو الخطة المجانية.

## نسخة مستقلة

eas.json يجهّز preview APK بتوزيع داخلي وAPI إنتاج HTTPS، دون تشغيل بناء سحابي أو نشر متجر. ملفات HAG الأصلية للأيقونة محفوظة. expo-notifications/expo-device/expo-constants أُضيفت بمتطلبات SDK58 الموجودة في بيانات التوافق المرفقة بـExpo؛ لم نرفع إصدار Expo نفسه.

scripts/configure-push.mjs يربط معرف EAS الحقيقي وgoogle-services.json العام المطابق لـnet.hagbrokers.mobile، ويتوقف إذا كان الملف مفتاح Service Account خاصًا أو المعرف الحالي مختلفًا. يحتفظ بنسخة app.json قبل التعديل. .easignore يستثني الأسرار والنسخ الاحتياطية وJSON الجذر غير المعروفة، ويتيح ملف Firebase العام اللازم للبناء. لا تحتفظ بمفاتيح Service Account داخل المستودع أصلًا.

## الخصوصية قبل التفعيل

راجع سياسة الخصوصية وممارساتك قبل تفعيل الخدمة: يعالج Expo Push Service ومزود النظام Google FCM على Android أو Apple APNs على iOS رمز الجهاز ونص الإشعار العام ومعرفات الربط والإشعار غير المباشرة وبيانات النقل اللازمة. قد تشمل المعالجة دولًا أخرى. لا يبرر النص أي نقل دولي أو معالجة دون الترتيبات المطلوبة. لا ترسل النصوص الخاصة أو الأسرار عبر Push. التحكم بالإذن والخيارات متاح، مع استثناء الرسائل العامة التي سبق إرسالها ولا يمكن سحبها مضمونًا.

هذه بنية قابلة للاختبار وليست شهادة اختبار وصول على جهاز. يلزم EAS/Firebase حقيقيان وAPK مثبت وتجربة حسابين قبل التفعيل للجميع. تفاصيل التثبيت والإعداد في README_AR.md بالحزمة.
