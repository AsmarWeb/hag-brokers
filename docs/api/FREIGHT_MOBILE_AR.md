# طلب عروض أسعار الشحن البحري — HAG

هذه إضافة للشحن البحري، مستقلة عن RFQ الخاص بالفرص التجارية.

- من «حسابي ← طلبات الشحن البحري» إلى نموذج ثلاث مراحل: الموانئ، الشحنة، التأكيد.
- حفظ الطلب في quotations الحالي، بنفس شاشة /admin/quotations الموجودة؛ إشعار إدارة باستخدام مسار quotation.created الحالي.
- العميل والمرجع والحالة من الخادم. لا دفع ولا حجز ولا تسعير تلقائي، ولا كشف لهوامش الإدارة أو عروض الناقلين.
- مسؤول الشركة أو مديرها بعد توثيق البريد وتفعيل الشركة والعميل؛ العضو العادي والفرد بلا ملف عميل لا يستطيعان استخدام الشحن. تبقى حسابات عملاء الويب القديمة صالحة إذا كانت نشطة وموثقة. لا ننشئ ملف عميل تلقائيًا للفرد ولا نغيّر صلاحياته.
- صفحات القائمة والتفاصيل خاصة بالشركة، مع تحديث بالسحب. اختيار الموانئ من البيانات الفعلية النشطة، بحث وصفحات (30 ميناء في الصفحة).
- مفتاح UUID للطلب، فهرس MySQL قصير وقفل عميل داخل transaction؛ تكرار نفس الطلب يعيد السجل، تغيير محتواه بنفس المفتاح مرفوض. بعد انقطاع الاتصال أعد نفس الطلب قبل تغييره. إغلاق شاشة النموذج يفقد المفتاح المحلي: افحص قائمة الطلبات قبل إنشاء طلب جديد.
- حدود: حتى 10000 حاوية، وزن إجمالي بالكيلوغرام حتى 9999999999.99، تاريخ YYYY-MM-DD. التحقق النهائي بالخادم؛ القيم ليست أسعارًا معتمدة.
- أُغلقت صفحات طلبات الويب أمام الحساب غير المرتبط بعميل نشط، وأصبح اختيار الموانئ النشطة والتحقق من الحقول مشتركين.

## الأيقونة

أيقونة assets/icon.png الموجودة تحمل HAG بالذهبي على خلفية كحلية وBROKERS أسفلها. إعدادات app.json تشير إليها وإلى ملفات Android adaptive/monochrome. لم نستبدل الهوية الموجودة بصورة أخرى. Expo Go يعرض أيقونته؛ معاينة أيقونة التطبيق المثبت تحتاج نسخة مستقلة. لا dependencies أو تغييرات app.json في هذه الإضافة.

## API

GET /api/v1/freight/ports?search=Jebel&page=1
GET /api/v1/freight/quotations?page=1&per_page=20
POST /api/v1/freight/quotations
GET /api/v1/freight/quotations/{id}

Bearer mobile:v1 مطلوب. AR/EN وCache-Control private,no-store كما في بقية API. لا تُفعَّل routes API القديمة المعلّقة.

## النشر والتحقق

ترحيل إضافي واحد: 2026_11_04_120000_create_freight_request_keys. انشر الخلفية وطبّق artisan migrate --force ضمن نشر معتاد مع نسخة احتياطية حديثة، ثم route:clear وconfig:cache وview:cache. لا db:wipe أو migrate:fresh. لا تعديل ENV أو الخطط المجانية أو وضع الصيانة. ثم حدّث التطبيق.

فحص المصدر واختبارات SQLite لا يثبتان أن الطلب الحقيقي وصل من هاتفك إلى MySQL الإنتاج. لا نُنشئ طلبات تجارية تجريبية في الإنتاج تلقائيًا. بعد النشر جرّب بحسابي شركتين: إنشاء، إعادة المحاولة، تفاصيل الطلب ومراجعته من الإدارة، منع شركة أخرى من قراءته، الحساب غير الموثق/الموقوف، وميناء غير نشط. تأكد أن الموانئ موجودة فعليًا من لوحة الإدارة؛ لا seed تلقائي.

لا يشمل هذا التحديث Push للشحن، مستندات PDF نهائية داخل الهاتف، تتبع الشحنات، حذف الحساب أو تعديل البريد. تبقى ميزات العروض والتنبيهات السابقة كما هي؛ تطوير دورة الحساب وPush مرحلة تالية.
