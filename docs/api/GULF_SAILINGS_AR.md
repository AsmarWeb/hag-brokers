# رحلات الشحن البحري في الخليج

المرحلة الأولى تعرض رحلات الحاويات الكاملة المباشرة التي ينشرها فريق HAG من بيانات الشركاء. تظهر السفينة والناقل والمسار والمواعيد وتُحفظ تفاصيل الرحلة المختارة مع طلب عرض السعر. حالة السعر والمساحة هي بانتظار تأكيد الناقل.

- الإدارة: `/admin/freight-sailings`. اختر ناقلًا نشطًا وميناءين، وأدخل مواعيد دبي، ثم احفظ مسودة أو انشر. إلغاء الرحلة يوقف الطلبات الجديدة ويحفظ تفاصيل الطلبات السابقة.
- الموقع: `/freight/sailings`. البحث متاح للزائر، وإرسال الطلب يتبع صلاحيات الشحن الحالية.
- الموانئ: موانئ دول مجلس التعاون النشطة ولها UN/LOCODE. لتفعيل ميناء قريب محدد، أضفه إلى دليل الموانئ وأدرج رمزه في `FREIGHT_NEARBY_PORTS` ضمن قائمة مفصولة بفواصل.
- التطبيق: `GET /api/v1/freight/sailings` يوفّر نتائج قابلة للعرض. مع طلب `POST /api/v1/freight/quotations` أرسل `freight_sailing_id` و`sailing_revision` من نتيجة البحث مع حقول الطلب الحالية. الطلبات السابقة لا تحتاج هذين الحقلين. لا توجد شاشة Expo جديدة في هذه الدفعة.
- كل مواعيد API بصيغة ISO 8601 UTC، ويعرضها الموقع بتوقيت دبي.

## فحص SeaRates عند توفر المفتاح

أضف `SEARATES_SCHEDULES_API_KEY` إلى إعدادات الخادم فقط. بعد تحديث كاش الإعدادات، شغّل من مجلد Laravel:

```bash
php artisan freight:searates-probe AEJEA SADMM
```

الأمر يجري طلب جداول مباشرًا ويعرض حالة HTTP فقط، مع رسالة عن صلاحية JSON. لا يستورد بيانات أو يعرض المفتاح. نجاح الاتصال لا يؤكد تغطية المسار أو توفر سعة. تتطلب المزامنة عينة فعلية وحسابًا مصرحًا له. الأسعار والحجز والعمولة تحتاج الربط التجاري المستقل المتفق عليه.

## تجربة محلية

بعد تطبيق التعديل، طبّق migration محليًا داخل حاوية التطبيق ثم شغّل اختبارات FreightSailingTest وFreightQuotationApiTest وQuotationFeatureTest. افتح صفحة الإدارة، وأدخل رحلة بناء على جدول الناقل، ثم اختبر اختيار حاويتين وحفظ الطلب. ألغ الرحلة وتأكد من اختفائها من البحث مع بقاء تفاصيل الطلب السابق.
