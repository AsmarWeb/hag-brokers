# حساب الهاتف والأمان

التطبيق يقبل حسابات الأفراد والشركات. حسابا Admin وSuper Admin لإدارة المنصة على الويب؛ لا يحصلان على mobile:v1 token. بعد كلمة مرور صحيحة يرجع login الرمز AUTH_ADMIN_WEB_ONLY لتوضيح السبب. بيانات الاعتماد الخاطئة تبقى 422 عامة دون كشف الدور.

PUT /api/v1/auth/password يتطلب Bearer بقدرة mobile:v1، كلمة المرور الحالية، كلمة جديدة 12–128 حرفًا مختلفة ومؤكدة. يحفظ الجلسة الحالية ويحذف الرموز الأخرى بما فيها رموز التكاملات، ويغير remember_token. لا ينشئ حساب شركة ولا يغيّر الأدوار أو صلاحيات النشر. لا يُدّعى إنهاء جلسات الويب الحالية؛ هذا يتبع سلوك جلسات Laravel الحالي.

platform:mobile-check فحص للقراءة فقط للجداول اللازمة. لا يطبع البريد أو كلمات المرور أو الرموز أو بيانات اتصال قاعدة البيانات. غياب الجداول يخرج بكود خطأ. لا يستخدم هذا الأمر لإصلاح البيانات أو منح صلاحيات.

## ملاحظة الإنتاج

أثناء الفحص رجعت /api/v1/app-config حالة 500، بينما catalog وopportunities رجعا 200 والحساب والعروض والتنبيهات رجعت 401 دون Bearer. يجب فحص migrate:status والسجل الخاص لتأكيد السبب؛ لا يمكن الجزم بأنه جدول مفقود دون نتيجة السيرفر. لا يثبت هذا الفحص نجاح دخول حساب حقيقي أو الكتابة على MySQL الإنتاج.

لا توجد migration أو dependencies جديدة لهذا التحديث. عند وجود ترحيل سابق pending، مثل 2026_11_03_220000_create_mobile_app_settings، يطبق ضمن نشر معتاد بعد نسخة احتياطية. لا تستخدم migrate:fresh أو db:wipe.
