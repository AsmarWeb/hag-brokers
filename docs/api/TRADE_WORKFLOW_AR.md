# HAG Brokers — API v1.2 للعروض والتفاوض والتنبيهات

12 مسارًا جديدًا؛ إجمالي API الهاتف32مسارًا. كل المسارات تحت /api/v1 وتحتاج Bearer mobile:v1 ومالكًا أو مديرًا ببريد موثق في شركة فعالة. تبقى المؤسسات معزولة، والأفراد والأعضاء العاديون ومسؤولو المنصة لا يدخلون هذه المسارات. لا Migration أو دفع أو اشتراك أو عقد ينشأ من هذه الحزمة.

## إرسال عرض
متاح لطلب شراء buy أو service_request أو procurement منشور من شركة أخرى. استخدم المعرف الرقمي الذي يعيده API للفرصة. المدخلات هي request_key UUID، quantity (حتى3كسور)، unit، unit_price (حتىكسرين)، currency، tax_basis، delivery_days، valid_until، payment_terms، confirmed=true، notes اختياري. وحدات وعملات catalog نفسها. المبالغ سلاسل عشرية، ولا يجمع التطبيق عملات مختلفة.
valid_until من اليوم وحتى90يومًا بتوقيت دبي، شاملًا نهاية اليوم. السعر الإجمالي base_amount يحسبه الخادم بدقة من الكمية والسعر؛ لا يُرسل من العميل، ولا يمثل فاتورة ضريبية أو تحصيلًا. tax_basis إقرار المورد ولا يُضيف ضريبة تلقائيًا.
يمكن إرسال JSON دون ملفات أو multipart/form-data مع attachments[]. حتى3ملفات PDF/JPG/JPEG/PNG، 5MiBلكلملف و10MiBللمجموع. يخزن النظام الملفات في rfq_private، ولا يعيد مساراتها أو hashes. استخدم download_path النسبي مع نفس النطاق الموثوق ورأس Authorization؛ لا ترسل الرمز إلى نطاق خارجي ولا تستخدم رابط ملف عام.
احتفظ بالمفتاح والحمولة والملفات وأسمائها وترتيبها لإعادة الطلب بعد انقطاع الاتصال:201عند الإنشاء،200عندالتكرارالمطابق. تغيير الحمولة مع المفتاح نفسه422. عرض واحد لكل شركة موردة/فرصة؛ مفتاح جديد لا يتجاوز هذا القيد. تطبق حصة التقديم الحالية ولا تتكرر عند retry. لا تعديل أو حذف للشروط المالية المجمدة.

## القراءة والقرار
القوائم مرقمة per_page1–50، page1–10000. direction=sent|received اختياري. المقارنة لصاحب فرصة الشراء فقط؛ المورد لا يرى عروض منافسيه.
العرض الصحيح يعيد integrity=true، version وأسماء الطرفين المجمدة وشروطه. sender_workspace_id وpublisher_workspace_id يحددان دور الحساب مع workspace_id من /me. لا يثبت اختيار العرض انعقاد اتفاق وساطة أو تحصيلًا.
عند integrity=false يعاد id وحالة السلامة فقط؛ امسح الشروط القديمة من واجهة التطبيق وأوقف الأفعال. الرسائل والمرفقات والسجل ترجع409 عند فساد سلامة العرض.
القرار: action=selected|declined|withdrawn وversionالحالية وreason10–1000حرف وconfirmed=true. المشتري يختار/يرفض، المورد يسحب. العرض المنتهي أو الفرصة غير المتاحة لا تُختار، ولا يمكن اختيار عرضين معًا. الطلب القديم أو القرار المكرر قد يرجع422 وفق الخدمة الحالية: أعدالتحميل واعرض الحالة، ولا تعاود اتخاذ القرار بصمت. السجل مرقم ولا يسمح بتعديل أو حذف الأحداث.

## غرفة التفاوض JSON
GET messages لا يعيد Blade أوHTML ولا يؤكد القراءة. كل رسالة تحتوي id/body/author_name/mine/created_at. اعرض النص باستخدام عنصر نص آمن، ولا تنفذه كـHTML.
بدون cursor: أحدث30رسالة بترتيب تصاعدي. after_id=آخرمعرف يعيد الرسائل الأحدث، وbefore_id=أولمعرف يعيد الأقدم. لا تجمعهما. limit1–50. meta.has_more يعني مزيدًا في اتجاه الطلب. عند استجابة فارغة احتفظ بالـcursor القديم. عند وجود دفعات جديدة متعددة استمر حتى has_more=false.
للتحديث الحي في التطبيق استخدم polling كل5–10ثوانٍ أثناء ظهور الغرفة، وأوقفه عند الخلفية/الخروج/401/403. احترم429 وRetry-After، ولا تجعل فشل الشبكة يمسح مسودة الرسالة. لا WebSocket أو Push في هذه الحزمة.
الإرسال يحتاج request_key UUID وbodyحتى4000حرف. التكرار المطابق لنفس المرسل يعيد نفس الرسالة200، والتغيير بنفس المفتاح422. الرسائل نصية غير قابلة للتعديل أو الحذف. writable=false تعني أن الغرفة للقراءة فقط؛ لا تعطل سجل المحادثة القديم عند إغلاق المصدر.
room.own_read_up_to وother_read_up_to حالتا قراءة شركتين؛ الحالة مشتركة بين المالك والمدير، وليست علامة لكل فرد. POST read مع up_to بعد عرض الرسائل لتأكيد القراءة. لا يمكن إنقاص المؤشر أو الإشارة لرسالة من عرض آخر. لا يؤثر GET في المؤشر أو إرسال البريد. خدمة البريد الحالية تتفادى رسائل المحادثة المقروءة وفق المؤشر نفسه.

## التنبيهات
القائمة لنفس المستخدم، مع فحص الانتماء الحالي للشركة وأهداف التنبيهات؛ لا تظهر سجلات شركة سابقة أو تنبيهات مستخدم آخر. الأنواع: rfq.submitted/selected/declined/withdrawn/message وmarketplace.moderation.hide/restore. تنبيهات الحساب العامة وmarketplace.application/decision القديمة ليست ضمن هذه القائمة.
النص عام ثنائي اللغة دون محتوى الرسائل أو الشروط المالية. offer_id/opportunity_id أهداف داخلية للتطبيق. GET لا يعلم التنبيهات كمقروءة؛ PATCH read صريح ويخص المستخدم الحالي. تعليم التنبيه لا يحدّث مؤشر قراءة الغرفة والعكس صحيح.

## المعدلات والأمان
الحد العام120طلبًا/دقيقة لكلIP. إرسال عرض15، قرار30، رسالة30، تأكيد قراءة60، وتعليم تنبيه60 لكل إجراء/IP. جميع القراءة الخاصة no-store. 401مصادقة،403صلاحية،404غيرموجودأوليسطرفًا،409سلامةبيانات،422تحقق/حصة/تعارض/نسخةقديمة،429معدل.
لا تلقِ الرموز في Logs أو روابط أو مستودع. تنزيل المرفق يحتاج HTTP عميلًا يرسل Authorization، ثم افتحه من ملف محلي مؤقت خاص بالتطبيق.

## الفحص والنشر
اختبر محليًا TradeWorkflowApiTest وCompanyTradeOffersTest وTradeOfferRoomTest وCompanyMailTest مع العزل الموجود. بعد الدمج route:clear وconfig:cache وview:cache ثم route:list --path=api/v1. لا اختبارات على MySQL الإنتاجي ولا فتح صيانة تلقائيًا.
هذه API للشركات التي لديها حسابات على المنصة؛ OAuth/مفاتيح شركاء وWebhooks خارجية وPush Notifications وإدارة الوسائط المستقلة ليست منفذة بعد.
