# API v1.1 — إدارة فرص الشركات

خمسة مسارات خاصة، بالإضافة إلى 15 مسارًا من الأساس:

| HTTP | المسار تحت /api/v1 | العمل |
|---|---|---|
| GET | /company/opportunities | قائمة فرص الشركة مع ترقيم الصفحات والاستخدام |
| POST | /company/opportunities | نشر فرصة مع وسائط اختيارية |
| GET | /company/opportunities/{opportunityId} | تفاصيل الفرصة الخاصة ومراجعتها الحالية |
| PATCH | /company/opportunities/{opportunityId} | تعديل الحقول المسموحة |
| POST | /company/opportunities/{opportunityId}/close | إغلاق الفرصة دون حذف |

## الصلاحيات
كل المسارات تحتاج Bearer mobile:v1 وبريدًا موثقًا وعضوية owner أو manager في شركة ومساحة نشطتين. العضو العادي والفرد ومسؤول المنصة لا يستخدمون هذه المسارات الخاصة. الفرصة التابعة لشركة أخرى ترجع 404. المسارات العامة بالـslug والخاصة بالمعرّف الرقمي الداخلي.

## النشر
الحد الأدنى: request_key (UUID جديد مرة واحدة)، title (حتى255)، description (20–20000 حرف)، opportunity_type من catalog، currency (ثلاثة أحرف)، expires_at (YYYY-MM-DD).
الدولة والمدينة والتصنيف والتفاصيل التجارية والمالية المسموح بها مثل نموذج الويب. expires_at إلزامي في API لتثبيت الطلب عند إعادة المحاولة؛ يعني نهاية اليوم بتوقيت دبي ويُخزن UTC. لا توجد ترجمة أو تحويل عملة تلقائيان.
أرسل القيم المالية كسلاسل مثل "100000.05" دون Float. احتفظ بـrequest_key والحمولة والملفات محليًا لحين تأكيد الاستجابة. أول نجاح 201/meta.created=true؛ تكرار مطابق 200/meta.created=false دون فرصة أو حصة إضافية. نفس المفتاح مع محتوى مختلف 422. إعادة المحاولة تبقى خاضعة لصلاحية الحساب والتحقق من الحقول وتاريخ الانتهاء.
لا يسمح بإرسال هوية الشركة أو الناشر أو slug أو حالة النشر والتحقق والإدارة؛ يحددها الخادم. لا ينشأ دفع أو عقد أو فاتورة.

## الصور والفيديو
النشر يقبل application/json دون ملفات، أو multipart/form-data مع media[]. أرسل commercial_details[subcategory] وvessel[listing_type] كحقول nested في multipart. الصور: jpg/jpeg/png/webp، الفيديو: mp4/mov/webm. 10 ملفات بحد أقصى و20MiB للمجموع و20MiB لكل ملف. عند retry أعد الملفات نفسها وبنفس الترتيب. ملفات المحاولة المكررة أو الفاشلة تُحذف؛ الملفات الأصلية لا تُحذف.
لا يوجد رفع ملف مستقل أو إضافة/حذف/استبدال وسائط لفرصة قائمة في هذه المرحلة. لا ترسل URL أو مسار تخزين كبديل للملف. الملف يرفع عند نشر الفرصة؛ تحرير الوسائط المستقلة يحتاج مرحلة منفصلة بعقد Idempotency خاص به.

## التعديل والمراجعة
GET الخاص يعيد revision من 64 رمزًا. أرسله في PATCH وPOST close. إذا اختلفت الحالة الحالية يرجع 409، حتى لو وقع تعديلان في الثانية نفسها أو تغيرت حالة الحجب الإداري. أعد التحميل واعرض الاختلاف للمستخدم قبل محاولة أخرى، ولا تستبدل revision بصمت.
PATCH يسمح title، description، category، country، city، notes، commercial_details وvessel. الحقول العليا غير المرسلة تُحفظ. commercial_details عند إرساله يحل محل الكائن بالكامل؛ أرسل كل تفاصيله المطلوبة. بيانات vessel غير المرسلة تحفظ، وعند إرساله تخضع حقوله لقواعد القوارب/اليخوت المشتركة. تغيير القطاع يتطلب subcategory مناسبًا أو مسحه صراحة.
لا تعديل لنوع الفرصة أو العملة أو القيم المالية والعمولات أو الموانئ أو التواريخ عبر هذا المسار، وفق سلوك تعديل الويب الحالي. لا تعديل لحالة الإدارة أو الملكية أو الوسائط. الفرصة المغلقة والمنتهية لا تُعدّل ولا تُفتح مجددًا. تعديل النص لا يزيل الحجب الإداري.
الإغلاق يحتاج confirmation=true. يحرر حصة الفرصة النشطة ولا يحذف سجلها أو عروضها أو ملفاتها. إعادة الإغلاق بمراجعة الحالة الحالية آمنة، أما مراجعة ما قبل الإغلاق فتُرفض 409.

## البيانات والقراءة
القائمة خاصة وتعرض notes لصاحب الشركة ومديرها؛ لا تعرضها للزوار. API العام لا يعرض الملاحظات أو العمولة الداخلية أو بيانات التسجيل الخاصة. راجع is_public لمعرفة الظهور الفعلي؛ published وحدها لا تعني أن الفرصة عامة. البحث العام وتواريخ SEO والحجب الإداري تعتمد الخدمات نفسها في الموقع.
القائمة: per_page من1إلى50، page من1إلى10000، state=published|closed اختياري. usage.active وusage.active_limit يوضحان حصة النشر. الحجب الإداري لا يحرر الحصة تلقائيًا وفق قواعد المنصة الحالية.

## الحدود والتشغيل
15 طلب نشر/دقيقة لكل IP، و30 تعديلًا أو إغلاقًا/دقيقة لكل إجراء/IP بالإضافة إلى الحد العام. 401 مصادقة،403 صلاحية،404 غير موجود/غير مملوك،409 مراجعة قديمة،422 تحقق/حصة/تعارض طلب،429 معدل طلبات.
لا Migration أو npm build أو تغيير Stripe لهذه المرحلة. الموقع وAPI يستخدمان OpportunityInput وOpportunitySubmission وCompanyMarketplaceService نفسها. سجل الطلبات والحصص والمراجعات المالية لم يتغير.

## الخطوة اللاحقة
API لعروض RFQ والمقارنة والتفاوض والإشعارات الخاصة والمرفقات المحمية. ليست جزءًا من هذه الحزمة.
